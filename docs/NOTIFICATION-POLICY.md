# 通知策略

MemPilot 会因为哪些事件、通过什么渠道、以什么频率打扰你——本文是唯一权威说明（v0.11.0 起的行为，代码与文档同步维护）。

## 渠道与分级

| 渠道 | 用途 | 频率约束 |
|---|---|---|
| **托盘气球** | 需要你知道但不必立刻处理的事 | 每类标题 **30 分钟冷却** |
| **主页横幅** | 当前有告急情况（内存/提交） | 常驻直到你处理或被新告警替换 |
| **非模态确认卡** | 需要你决策的事（L3 关闭闲置后台、低可用兜底的"继续压缩"） | **30 分钟冷却**（L3）／20 秒无响应按安全默认处理（低可用兜底） |
| **状态栏动作反馈** | 你操作的结果 | 保留 60 秒（刷新文案不会覆盖它） |
| **决策日志** | 一切自动决定的完整记录 | 不打扰，事后查 |

**模态 MessageBox 只用于破坏性确认**（L4 强制结束、腾内存计划执行、出厂重置等），
信息类通知一律不走模态框。

## 托盘气球白名单（仅这四类会发）

| 事件 | 说明 |
|---|---|
| 内存/提交告急 | 引擎 Alert 触达；冷却 30 分钟 |
| 租约侵蚀告警 | 占用期可用跌破授予下限 |
| 模式切换 | 自动切换或手动切换时 |
| 用户主动长操作完成 | 腾内存执行完毕（你主动发起的，切走了也该知道结果） |
| 垃圾进程建议（v0.15.0） | 整天未使用的垃圾进程——**每天最多 1 次**，引擎侧保证；v0.17 起只在**本地 19 点后**评估（午夜评估会让所有进程都算"今天未使用"），托盘模式未交付则自动重试、不消耗提示冷却；设置页可「立即检查」手动触发 |

**不发**的：设置已保存、一键回收完成（结果在状态栏 60 秒 + 审计页）、周期性提示
（GrowthWatch/HabitHint/CommitWatch 只进决策日志）。

## 自动兜底必须解释，用户主动操作不必

**这条是 v0.24.0 新增的划分**，因为真机上出过一次误会：用户在跑 AI 任务，MemPilot 因可用
掉到 2.6 GB 自动压缩了 152 个进程（回收 4 GB），用户体感是"清理后变卡"——而压缩本身
**没有撤销 API**（页面换出后只能等进程下次访问读回）。他需要知道的不是"清理完成"，
而是"刚才发生了什么、为什么会慢、要不要做什么"。

| 动作 | 是否解释 | 渠道 |
|---|---|---|
| 用户点"一键回收"/批量处置 | **不解释**（他知道自己干了什么） | 状态栏 60 秒 + 审计页 |
| 引擎自动兜底（低可用压缩） | **解释** | 托盘气球 + 状态栏；**不占主页横幅** |
| 引擎自动兜底但用户关了开关 | **解释"没做"** | 同上，文案说明需要手动执行 |

**为什么走托盘而不是主页横幅**：横幅只在主页 Tab 可见，而且 `RaiseAlert` 每次直接覆盖
（没有队列）——拿它解释"刚才为什么卡"会把"内存仍然告急"盖掉。而"卡"的体感是跨页面的，
托盘气球才是唯一跨页通道。

## 低可用兜底的两档（v0.24.0）

| 可用内存 | 动作 | 提示 |
|---|---|---|
| ≥ 3 GB | 不动 | — |
| **1.5–3 GB** | 先温和压缩（前 20 个）→ 弹卡问是否继续 | 托盘说明 + 确认卡（20 秒无响应 = 不继续） |
| **< 1.5 GB** | 全量压缩（防 OOM，不问） | 托盘说明 |

关闭「自动提交兜底」后：1.5–3 GB 只通知不压缩；**< 1.5 GB 仍然压缩**（不压会 OOM），
决策日志会写明"危急档强制执行"。这个顺序（危急先于开关）有单测钉住。

## 决策日志"只记录"的事件

这些事件只写 `decisions.json`，不主动打扰——它们是提示不是告急：

- `GrowthWatch`：后台进程工作集增长超 800MB（每 PID 48 小时最多 1 条）
- `HabitHint`：历史画像显示某时段内存常态偏低（每时段每天 1 条；同时更新主页"时段画像"卡）
- `SceneShadow`：影子模式判定"如果自动切换会切到哪"
- `PromoteRule` / `RuleAudit`：规则晋升建议与每周规则体检（建议项会出现在主页"待处理"卡）

## 总开关

设置 →「重要提示触达」（配置键 `ShowAlerts`）：关闭后 **CommitWatch / HabitHint / 低可用兜底的
解释性通知** 全部静默，只写决策日志——"只观察、不打扰"模式。

**已知不一致（v0.24.0 只把新路径接上）**：租约告警、AI 会话结束、垃圾建议、模式切换、
腾内存完成这几条目前**不读** `ShowAlerts`。旧文档写"关闭后全部静默"与实现不符，已按实际
行为改写；老路径的统一收敛单独处理，不在本次功能提交里混重构。

## 附：压缩与挂起能"恢复"吗

| 动作 | 可逆？ | 说明 |
|---|---|---|
| **L1 压缩工作集** | **否** | `K32EmptyWorkingSet` 把页面移到 standby/页面文件，没有反向 API；进程下次访问自然读回。所以策略只能是"少压 + 提前说" |
| **L2 挂起** | 是 | `NtSuspendProcess` / `ResumeThread` 成对，账本落盘 `suspended.json` |
| 定时挂起 | 是 | 到期自动恢复（5 秒探针） |
| 租约挂起 | 是 | 归还/过期/续期时恢复；**崩溃重启后由 v0.24.0 的孤儿恢复兜底**（30 秒后自动唤醒） |

因此"内存空闲后主动恢复"只对挂起有意义；对压缩不存在这个操作。而挂起的自动恢复有三条：
到期、租约结束、孤儿恢复——**不存在"压力消失就恢复"**，因为非租约的自动挂起本身不存在
（所有非租约 L2 都要用户点击）。
